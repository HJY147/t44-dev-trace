- 派工标识：ROLE-testing-BOOTSTRAP-v1；当前阶段 bootstrap，仅验收设计。
- 本实例无父会话上下文启动；只收到实际派工消息并读取本岗位 TASK.md 与白名单原始材料。
- 没有业务实现；没有运行被测系统、测试、覆盖率或压测，没有测试通过结论。

## 当前输入与通信边界

1. 输入白名单仅为本岗位 TASK.md、T44-taskbook.txt、submission-notes.txt、homework-requirements.txt、manifest.json；具体 SHA256 记入 WORKLOG.md 及 testing.json。
2. 不读取其他岗位、开发日志、提示词、设计讨论、内部接口草案、docs/、其他 records/ 或 reports/；不浏览项目文件清单寻找开发信息。
3. 不使用 collaboration 消息、派工、代理列表工具，不与其他 agent 交流。最终交接只返回总协调。
4. 写入仅限本任务指定的五个路径。本次共享文件系统只形成流程约束，不代表已经实施操作系统级隔离或技术上禁止越界读取。
5. manifest 的原始 DOCX 哈希只是来源声明；原始DOCX不在读入白名单，未重新验证，也未读取其中图片。输入不足需正式追加批准，不自行绕过。

## 用例和证据约束

- 黑盒用例至少包含用例ID、FR/AC来源、前置条件、输入/步骤、批准的预期响应及状态/审计断言、清理方法、规格疑问状态。
- 并发验证显式同步两次更新与同基线版本，区分竞争拒绝、幂等重放与后续合法更新；规则由正式规格决定。
- 20条超期任务建立固定ID清单；每条扫描、升级、投递/消费、通知或故障降级都可关联，不能用总数相等代替逐条核对。
- 流转与留痕原子性结合故障点和重启证据；外部结果只能支持被覆盖路径，不能单独证明所有内部路径。
- 每请求性能记录至少包括时间戳、接口/操作、请求ID、耗时、状态/错误；保留原始数据、分位数算法、吞吐窗口、脚本与完整复现命令。
- 安全证据必须脱敏；使用测试凭证和合成数据。不能仅靠扫描无告警就断言所有入口无越权、所有SQL参数化或Token不泄露。
- 不生成虚构AI历史或人为凑齐修改/幻觉数；文档材料审查与功能运行结果分开记录。
- 缺失/矛盾规格标为待澄清；未运行标为未验证；失败与环境阻塞分别报告；不把静态阅读称作动态测试。
