## 职责与字段设计范围（草案，未冻结）
- 未来代码责任目录：`database/`、`backend/app/persistence/`；本轮未向这些目录写入模型、DDL或迁移。
- 任务核心表：项目归属、负责人、计划时间、业务状态、阻塞原因/责任环节、解除依据、并发版本及审计关联。
- 依赖核心表：前后置任务关系、依赖满足依据；排期/产能/缓冲/延期预案的归属待后端确认，不擅自合并为已定字段。
- 评审核心表：评审对象/版本、八段式记录、十项清单逐项证据及结论；证据结构与扩展方式待后端确认。
- 决策核心表：上线/回滚对象、四视角风险、应对及回滚预案、评审关联、拍板人、决策时间与依据。
- 必要辅助数据候选：项目/成员权限、状态与排期变更审计、拒绝审计、请求幂等、升级记录、待投递事件、消费去重及通知。
- 辅助数据是否独立建表、关联及清理策略均待责任岗确认；通知仅设计一套共享持久化数据，由消息岗确认业务契约。
- 主键候选统一 `INT UNSIGNED`，按实际增长边界复核；布尔/枚举候选 `TINYINT UNSIGNED`，集中定义含义，禁止散落魔法值。
- 时间候选以 UTC 存储并明确精度；长度、空值、默认值、删除策略及约束按字段字典逐项审定，当前无完整字段字典。
- 索引候选覆盖项目范围查询、计划时间扫描、依赖双向查询与幂等唯一键；无已创建索引或性能结论。

## 对接输入输出（全部未冻结）
- 后端 → 数据库：三类接口字段、ID/状态枚举、迁移表、权限过滤范围、错误映射、幂等请求协议和事务边界。
- 数据库 → 后端：待评审的字段字典、持久化输入输出、约束与冲突条件；并发更新拟以任务版本比较，仅一次成功。
- 成功状态更新与状态留痕须同事务；拒绝更新不得改动任务现状，拒绝审计如何独立提交须由后端共同确认。
- 消息 → 数据库：事件/投递/消费标识、版本、载荷、消费者幂等键、通知查询/已读及降级待办字段要求。
- 数据库 → 消息：待投递事件、去重与通知持久化边界候选；提交后投递、失败重试和站内待办的原子性方案待共同确认。
- 调度 → 数据库：临期/超期判定时区、扫描时间窗、升级级别规则、完成/回滚等排除状态和续扫要求。
- 数据库 → 调度：分页扫描与升级记录候选；幂等业务键需覆盖任务、规则版本、级别及计划变更语义，尚未选定。
- 候选错误条件包括资源缺失、参数/约束无效、状态/版本冲突、权限拒绝及幂等冲突；HTTP/业务错误码由后端提案并经总协调冻结。
- 部署后续需确认 MySQL 版本、字符集、时区、连接配置、备份恢复及迁移执行主体；本轮未实际对接部署。
