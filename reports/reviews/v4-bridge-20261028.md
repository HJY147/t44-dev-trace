## 4. 接口与数据库兼容：两项阻断

**V4-BRIDGE-01，P1，backend owner。** `bridge_backend.py:183–196` 的 `generation()` 只传 phase 与 binding SHA（token/rotate另有project ID），没有 `--budget-receipt` 和 `--budget-receipt-sha256`。v4 wrapper 对 scheduler-token/rotate/start 都调用 `budget.admit(...args.budget_receipt,args.budget_receipt_sha256)`；CLI默认两者None。该准确组合在发实际 GEN 操作前必拒，不能完成新回调。

本岗在 macOS Python3.12 用从161 Git blob原样提取的 `generation` 函数和无进程 Capture runner执行 scheduler-token，实际捕获 argv 确认两flag均缺失；从b592 Git blob原样加载实际 `budget.admit`，输入None后在接触runtime之前得到 `EXPLICIT_CURRENT_PHASE_BUDGET_RECEIPT_AND_SHA_REQUIRED`。没有启动controller、Docker或数据库。证据见 [准确接口探针](../../agents/reviewer/evidence/v4-bridge-20261028/exact-interface-probe.json)。

**V4-BRIDGE-02，P1，backend owner。** `bridge_backend.py:333–338` 的 `_data()` 锁内直接运行 preflight/seal SQL容器，只检查deadline；`phase_operation_lock()` 只装载准确helper、核binding与取锁，没有 `budget.admit`。首个preflight在上述GEN拒绝前就会访问MySQL，因此不能声称所有SQL步骤都经同实际MySQL身份与容量准入。应把准确预算收据path+SHA纳入受绑定的PUBLIC配置/authority，每次direct SQL前锁内admit，并向GEN逐次透传。停止、旧nonce及旧结果不应为此改写。不得把单纯互斥当作预算准入。

## 5. 期限、权限与失败行为

桥保留 request.requested_utc+120秒与grant/launch/supervisor/binding最早截止；LOAD同机用hard_deadline_monotonic作额外上界。APP只接受不超过30秒的LOAD快照，租约最多80秒且预留10秒返回，实际APP操作最多60秒/开始至少剩45秒；这不是跨机持续存活证明。LOAD交付重新读所有原件、核pending nonce、container/host PID birth/PGID/namespace及UTC+monotonic，再以同目录临时固定FD、fsync、hardlink不覆盖发布。进程活性检查与文件提交并非同一个原子事务，代码回执已如实明示。

APP固定同phase `.scope-callback-state`，grant+nonce独占预留；mutation后失败留quarantine，后续nonce不能换目录绕过。自己的CLI子进程超时可杀自己尚未回收的进程组，Docker守护端动作仍可能迟到，失败保留private stdout/stderr和inflight事实，不能宣称回滚。Token/K只在data-only容器中读取和密封，PUBLIC传递opaque；未发现本scope内把secret写进CLI argv或PUBLIC输出的新路径。该桥核进程存活及有限快照，不提供宿主外部guard心跳持续健康的独立证明；新的Linux守卫及运行时准入须另外提交实际证据。

v4 wrapper对 stop/status 直接走旧操作出口，在加载预算模块、等待mutex和查预算之前返回。旧 `operate` 的stop位于有效窗口和业务动作之前，phase_binding采用stopping=True，因此预算缺失/上限不够不应封死整phase停止出口。此为静态入口核对，未实际运行Linux/systemd/Docker停止。
