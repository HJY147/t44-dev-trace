# 数据库范围的下一批规模优化审查

本轮基线是 `f7cdb5fa3b19f84d8ab0d0b042bf51a5b8484e8f`。总协调明确本岗可修改持久化、种子与迁移实现；初始化 TASK 的“只写设计”是旧阶段记录，不能据此拦住当前已授权开发。操作者为数据库岗位 AI。

目标是删除真实重复，保持公共输入/返回、错误文本与顺序、SQL/事务和历史库兼容。禁止压行、将实现移入不计数文件、删校验、修改原测试。准确云版本仍由总协调维持 f7，本分支不接触云、会话或独立测试资料。

## 检查过的边界

| 区域 | 原有共享机制 | 不能当重复删除的部分 |
| --- | --- | --- |
| `seed.py` | `_populate.add` 按冻结 TABLES 过滤共享 context；统一 annotations、按需表 buffer 与 FK 顺序分批写入 | 各状态的版本、独立评审、批准引用、回滚决定、时间轴、marker 和空库拒绝条件 |
| `schema.py` | 元数据由校验摘要的冻结 DDL 解析生成，没有第二份列清单 | CHECK/外键/默认值与 MySQL/SQLite 方言转换 |
| `rows.py` | `_fields` 统一允许列表/嵌套 SQL 表达式拒绝，`_execute` 统一结果与故障分类 | insert/update 的不同非空条件、predicate/排序/分页/锁检查顺序，以及失败事务标记 |
| `migrations.py` | CHECK、索引、外键签名各自归一化；native catalog 统一查询/比较循环 | 反射缺失的字符集、索引方向/可见性、CHECK enforced，以及迁移锁/partial-DDL 拒绝 |
| `uow.py` / `accounts.py` | 单一事务入口与明确结果边界 | commit-uncertain 与 rollback/close 不可合并成通用吞异常路径；密码拒绝审计须独立 UoW |
| `delivery.py` | `_notices` 共用通知落库，claim 共用两阶段算法 | confirm/consume/fallback/retry 的不同前置条件、状态和锁生命周期 |

## 本轮取舍

1. `insert_many` 与 `update_many` 只有“逐行 `_fields`”和空批返回两步相似。增加私有 dispatcher/保留两个公共 wrapper 需要增加分支及参数，不能证明有可维护且正向的规模收益，未实现。
2. native catalog 的四类预期值/查询分别描述不同的 MySQL 属性；现有统一比较循环已消掉重复执行逻辑。把这些属性移入额外 SQL/JSON/工具或用动态字段 DSL，既不满足当前统计规则，又扩大兼容风险，未实现。
3. seed 的共享 context 和 annotations 已覆盖实际共用值；继续塞入只用于一张表的字段不删除重复。改变构造顺序、VERSION、golden 或业务状态以缩短代码会改变 fixture 契约，未实现。
4. 迁移和事务的清理分支外观相似，失败含义却不同。未以缩短行数为由合并异常/commit/锁释放路径。

本轮先停止产品改动，实测当前固定 cloc 并生成产品/原测试逐字边界证据。没有候选代码就不制造测试、产品红例或性能收益。本轮结论只限当前有界数据库审查，不能证明整个系统不可能进一步精简，也不能关闭规模、正式性能或独立验收门禁。

后续若调整为跨模块重新建模，须由总协调单列接口和错误顺序设计、安排责任岗与审核，不能把大范围重写称作本轮安全的小重构。
