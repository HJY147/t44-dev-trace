# v7 neutral schema-helper maintenance

The only changed executable core file is the private schema helper. Its type dispatch previously indexed a dictionary with the JSON Schema `type` value. A legal array such as `{"type":["integer","null"]}` therefore caused `TypeError` before validation of the instance.

The replacement first checks the complete type declaration, then accepts an instance if any declared primitive predicate matches. Unknown names, non-string members, empty arrays, duplicate names, and declarations that are neither a string nor array raise explicit schema errors (`ValueError`). Such errors are not swallowed by existing `anyOf`/`oneOf`/conditional instance-mismatch handling. Wrong instance types still raise the existing `Invalid`. A successful type match continues into all existing constraints; it does not return early.

The seven original primitive predicates and all code outside this dispatch statement are AST-identical. The preexisting integer predicate uses Python `int` and excludes booleans. This narrow repair retains that subset; it does not claim complete JSON Schema compliance, including integral Python floats. Numeric/string/object/array constraints, local refs, composition, the business suite, contract, assertions and performance thresholds were not changed. Type union semantics were checked against [JSON Schema 2020-12 validation §6.1.1](https://json-schema.org/draft/2020-12/json-schema-validation#name-type).

The PUBLIC checker imports only a named schema helper. Its cases contain generic synthetic schemas/values, never private case payloads. It rejects socket audit events and does not import or execute the business runner. It covers both type-list orders, integer and null acceptance, string and bool rejection, all seven singleton unions, overlapping types, malformed declarations, constraints, composition, local refs and nested values. The old v6 helper executes 89 offline checks with 87 expectation failures (including the original `TypeError`); this red evidence is retained. The repaired v7 helper passes 89/89. These are tool checks, not business cases or SUT requests.

Prior controller checks remain versioned: v5 36 no-socket checks; v6 reran those same 36 and added 3 lifecycle no-socket checks plus 4 actual synthetic TLS canary requests. v7 did not rerun those checks or canaries; the five PUBLIC core files are byte-identical to v6. This maintenance made 0 SUT requests, 0 socket calls, 0 API/DB/MQ calls, 0 TLS canary requests, and no clock changes. It did not regrade or alter any prior published execution facts, encrypted evidence or keys.
