## Execution/proof changes — explicit

1. A bounded page reader records every page total, cardinality, returned count and unique-ID count. It visits at most the page count derived from the first total, capped at the unchanged100000-page safety bound. It never chases a writer or automatically rescans. Legal total growth/shrink is a dynamic observation. Stable missing pages, duplicate IDs and per-page cardinality contradictions produce incomplete-enumeration evidence. Stable enumeration does not establish an atomic snapshot; snapshot status is always NOT_PROVEN for this page-only contract.
2. Performance's preliminary audit read is observation-only. It no longer aborts the timed workload merely because the audit total changes. The original workload operation,400-worker cohort,30-second warmup,600-second steady interval,metrics formula,all original performance check calls and thresholds are AST-identical. Each cohort and metrics record is durably appended before resource analysis or postcondition checks. Resource raw bytes are imported next, before any later criterion/postcondition exception can discard those observations.
3. Exact complete-audit postconditions retain their expected values. They are not marked passed when no complete baseline/final audit snapshot can be proved. Other observable final-state/history/event/recipient checks remain. Complete-postcondition and complete-formal-group counters advance only after all proof guards. **Under the current page-only authority, the exact audit snapshot gap leaves complete formal acceptance NOT_PROVEN even if all measured core metrics meet thresholds.** A completed400-client/600-second core interval and a complete acceptance group are separate counts. Actual core errors still fail their original checks; missing resource/audit evidence does not convert them into a pass.
4. Resource input is parsed from exact raw JSONL bytes streamed into authenticated encrypted journal chunks before parsing. Real finite nonnegative numeric pairs count as samples;null is missing,boolean/invalid/nonfinite values do not count. Null/pending rows,invalid lines,partial tails,missing IDs and largest numeric gaps remain visible. No numeric-only source,zero fill,interpolation or coverage from missing rows is used. The former10-second endpoint tolerance remains; v8 additionally rejects a gap between numeric pairs greater than10seconds as insufficient sampled coverage. This is an explicitly stronger evidence-completeness convention, not an altered product latency/throughput threshold. Sampled coverage does not prove unsampled continuous values. The source hash covers actual bytes read; it does not include future appends.
5. The neutral account interface now documents optional environment.accounts.expired.token and genuine natural expiry, including60s TTL. It adds no auth action or permission. No real token is in PUBLIC.
