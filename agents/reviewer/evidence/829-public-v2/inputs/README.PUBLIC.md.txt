# Independent acceptance tool 829 — PUBLIC integration contract

This folder is explicitly PUBLIC. All sibling `private/` content, private Git objects, acceptance cases, run logs and keys are out of bounds to the root/development roles. This is workflow isolation on a shared filesystem; no OS isolation is claimed. The operator is AI. No student manual test, human review or runtime manager decision is invented.

The entry point for review is `manifest.PUBLIC.json`. `control.py` is the reviewable network/time/resource/fault boundary. `routes.PUBLIC.json` lists the exact method/path patterns it permits; it contains no cases. Private frozen logic is present locally and also packaged as `suite.bundle.PUBLIC.aes`; root may transport this ciphertext as opaque bytes. Root does not need a decryption key or access to cases. The bundle is authenticated with encrypt-then-MAC; the independent operator keeps the key. Public SHA-256 permits byte-preservation checks. No opaque package is to be executed by root.

Startup rehashes every frozen tool file against the private inventory and public commitment before opening the network gate. Symlinked or changed files fail closed. Before an explicitly admitted run the tool performs **zero SUT HTTP requests**, including DNS, health checks and discovery. Offline tests substitute a socket constructor that raises immediately and use no listening HTTP mock. Once admitted, all SUT requests pass through `Gate.request`: exact HTTPS origin and pinned IP, TLS hostname/CA validation, no proxy, no redirect, fixed route allowlist, no automatic retry, at most 400 in-flight requests, at most 250000 requests and at most 2400 seconds per phase invocation. A request may finish at most its 30-second timeout after admission expires; no new request may start then. A response over 16 MiB is incomplete and cannot count as a complete case. Evidence is capped at 8 GiB of plaintext before streaming encryption, after which the run fails closed. The boundary opens no cloud resources and executes no fault shell commands.

Every request records UTC start/end, monotonic start/end/duration, phase, case pseudonym, request method/path/headers/body, actual HTTP status, raw ordered response headers, complete binary body as base64, transport exception and completeness. Authentication tokens/passwords therefore live only inside encrypted raw evidence. Ordinary summaries contain no credentials. Raw evidence is streamed through `/usr/bin/openssl` AES-256-CBC with PBKDF2-HMAC-SHA256 (200000 iterations) and authenticated with an independent HMAC-SHA256 key. Verify HMAC before decryption. The passphrase is delivered through an inherited FD, never a command argument or environment variable. Keys stay under private/secrets with mode 0600.

## Inputs

`admission.template.PUBLIC.json` is a shape example and is **not authorization**. Root supplies an explicit grant bound to the frozen tool SHA, exact source SHA, image digest, HTTPS base `/api/v1`, pinned IP, CA path, exact isolated resource IDs, UTC expiry, request/time/concurrency caps, allowed faults and operator `AI`. Empty/nonpositive limits or missing identity/isolation/build metadata fail before a network request. Grant only the next phase; never infer performance or faults from functional admission.

`environment.template.PUBLIC.json` describes neutral role/session/fixture data. Required disposable human identities are manager `m`, developer/owner `d`, alternate developer `d2`, independent reviewer `r`, project outsider `x`; `s` is a separate project-scoped service identity. Dedicated `expired` and `revocation` sessions are optional; absent prerequisites are NOT_PROVEN. Account IDs/usernames must identify actual initialized disposable accounts. The tool creates no identities or external permissions. Root may supply existing tokens or arrange credential delivery; no guessed account, token or endpoint is used. If supplied credentials need login, the independent operator will use the frozen login interface only after admission.

Performance additionally requires an existing isolated project/iteration, two disjoint 400-ID task pools, complete synthetic-dataset project inventory/provenance, server machine topology and a resource JSONL file transported into `private/input`. The 400 transition tasks start in development, have the owner `d` and plan end over 48 hours away. The 400 escalation tasks are active and at least 24 hours overdue. Resource rows use `utc`, `resource_id`, `cpu_percent`, `memory_bytes`; IDs must cover the granted isolated resources and timestamps must cover the steady interval. Secrets and incoming files are copied to private/input by the independent operator. Root must not inspect the private destination afterward.

Use separate isolated database snapshots for functional, fault and performance phases. Functional/fault cases intentionally create synthetic fixtures; the contract has no project deletion endpoint, so the tool does not claim cleanup. Reset/removal of supplied isolated resources is a root-controlled, separately authorized action. Benchmark inventory is verified by public pagination before performance, with a frozen ±5% interpretation of the taskbook's approximate 40/6000/9000/15000 counts. No benchmark fixtures are added after inventory.

## Execution

The independent operator, after root technical review and explicit admission, runs:

```
python3 private/suite.py --grant private/input/grant.json --environment private/input/environment.json --phases functional
python3 private/suite.py --grant private/input/grant.json --environment private/input/environment.json --phases fault
python3 private/suite.py --grant private/input/grant.json --environment private/input/environment.json --phases performance
```

Run these from the independent workspace; root need not read private code. The only dependencies are Python 3.12 standard library and `/usr/bin/openssl` supporting `enc -pbkdf2`. The public boundary itself is readable in full.

Fault actions are handshake-only: the tool writes a request under `PUBLIC/signals` with action, nonce, isolated resource IDs and deadline. Root performs only an already-authorized isolated-resource operation, then writes a matching `.ack.PUBLIC.json` with `nonce`, `action`, `completed: true`, `completed_utc`, exact resource IDs and actual command/result metadata. No acknowledgment is fabricated. The tool waits at most 120 seconds per handshake and then stops that case. Recovery requests are always attempted in the MQ outage case. The grant's UTC expiry always applies. Root controls any out-of-band resource restoration after expiry.

## Frozen metrics and proof boundaries

Planned cases, offline tests, actual SUT requests, completed postcondition checks and completed formal performance groups have distinct counters. An HTTP success alone never completes a functional case. Functional mutations include latest-state reads, all contract-visible dependency/review/assessment/decision histories and persisted success/rejection audit checks. Missing public observability is NOT_PROVEN rather than an invented invariant.

The formal cohort has 30 seconds of excluded warmup and a fresh 600-second steady clock; 400 synchronized closed-loop virtual clients must all remain live for the entire steady interval. Eight of each 20 operations are real task transitions, six task queries, four contract validations, two service escalation requests. Latencies include connection/TLS/body time. P95 uses nearest rank separately for task transitions, contract validation and escalation (limit 270 ms); throughput counts completed requests inside the 600 seconds and must be at least 1000/minute. All business/transport/schema failures are failures; no expected 409 is silently removed. Boundary/drain requests stay in raw records and do not inflate in-window throughput. Generator CPU/memory and active request counts are recorded. 400 virtual clients are not misreported as exactly 400 continuously in-flight network calls.

Escalation steady traffic exercises the real existing-event deduplication path after the scheduler has stabilized. It does **not** prove new-event creation throughput; this limitation remains explicit. New-event delivery/fallback behavior is separately exercised by functional/fault cohorts. A formal group completes only after the full timed cohort, all worker resources' state/history/audit/notification checks and correlated server resource evidence are complete. The tool does not generalize a short run or deduplication workload to unmeasured paths.

All 38 authority operations and 551 declared operation/status/error-code branches are catalogued privately. Executed coverage is reported separately; unexecuted branches remain NOT_PROVEN. Physical DDL/storage/hash/SQL parameterization, source architecture/size, coverage, PR merge gates, frontend display, source changes and human AI-trace history cannot be proved by these public HTTP interfaces. A passing implemented subset cannot be presented as complete AC01–AC09 acceptance. Editing-stage status labels in authority files are not treated as deployed-service status.
