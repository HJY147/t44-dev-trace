# Isolated Request-ID candidate verification

The two production candidate files are `deployment/nginx/nginx.conf` and `deployment/nginx/api.conf`; this is a new candidate, not a change to running C. Only one full lowercase canonical UUIDv4 upstream value is retained. Missing, empty, malformed, wrong-version/variant, uppercase or duplicate/comma values use the nginx local ID. Upstream response fields are hidden before one server-level field is emitted. API code, client distrust, body/error envelopes, local413, static/security-header inheritance, TLS, DB and business rules remain unchanged.

`tmp/deployment/840_nginx_request_id.py` is an explicit hosted-Linux driver, not pytest-collected cases or an independent acceptance script. It starts only a synthetic loopback upstream and two successive owned nginx containers. It never accepts a target URL, credentials or arbitrary image/source. The fixed digest is read as declared in the driver and matches C's web Dockerfile. The real nginx receives byte-identical candidate files, runs nonroot with read-only mounts/rootfs, and runs `nginx -t`. The baseline is retrieved from immutable `30afdefaeb7427ec3b582a85373d5143124e0581` rather than reconstructed from the candidate. Its one-header assertion must fail with two actual raw fields. Candidate responses must contain exactly one selected field and all three inherited security headers.

The 23 candidate paths cover success/repetition, 401/500, synthetic replay success/error, client spoof, mixed-case header names, absent/empty/invalid/uppercase/non-v4/bad-variant, same/different/mixed-case duplicate headers, explicit comma list, proxy-local413, upstream413 after a >1MiB body, upstream disconnect502, static and SPA fallback. Local413 may reject the declared >2MiB Content-Length before consuming the full body; request send completion is recorded separately. Replay/auth behavior is fixture-only, not a test of the real API or its persistence. This job has no TLS gateway and makes no claim about a complete web build, C deployment, independent acceptance, performance or a teacher-mandated equality requirement.

`.github/workflows/nginx-request-id.yml` triggers only an exact branch push to `codex/deployment-request-id-chain` changing `agents/deployment/request-id-chain/run-request.json`, with read-only repository permission, no secrets, no retained checkout credentials and a 10-minute job/480-second driver bound. A reviewable code commit is published first. Only after review a separate request pins that implementation SHA (`candidate_source_sha`, 40 lowercase hex; mode `synthetic-pinned-nginx`). Driver verifies it is an ancestor and current config/driver/workflow bytes are unchanged. Missing Docker/image/syntax/request evidence is a real failure, never a skip.

Command receipts, original raw header blocks/tuples, synthetic responses, source/image identities and any failure are retained in the single artifact `nginx-request-id-<executionSHA>`/`receipt.json` for14days. Only that synthetic evidence is downloaded to this role's evidence directory; no cloud or independent material is read. Local checks do not substitute for this runtime result. The current stage/result must be read from the role evidence and actual run URL; a prepared workflow alone is not a pass.
