## 下次运行顺序

1. 先只恢复原压力机 0mu（16核）。原64核应用机 0mt保持停止，直到连接、传包和工具安装完成。由用户决定何时恢复；不要提前启动两台等待排障。
2. 在压力机云助手运行 `01_INSTALL_TEMP_SSH.USER_ONLY.sh`。脚本仅用于用户当次明确允许的临时root公钥连接：有效期从实际安装起2小时，禁止转发；不改安全组、网络防火墙、密码或实例状态。它校验现有sshd配置，保留已有authorized_keys，只启动已安装的SSH服务。若SSH未安装或不支持当前公钥登录配置，报告并停止，不自动放宽策略。

   两小时到期只阻止新的SSH认证，不会自动终止已建立的连接、SCP或远端进程。任务结束后必须主动退出连接并移除本次临时授权；不能把密钥到期当成进程自动停止或云实例停止。
3. 保存该命令的完整公开JSON回执，用 `pin_ssh_host.py` 绑定本实例实际主机公钥。公网IP从用户当次页面提供；脚本拒绝不匹配实例、过期回执和已知主机密钥的静默替换，不自动接受未经核对的host key。
4. 执行一次只读SSH连接，成功后通过SCP传送独立岗已发布的 `MANUAL_TOOL_V4.PUBLIC.tar.gz`（86788字节，SHA256为 `0b3d4d6ba68dc1fa27930963b9442b0bf8e2c2ae61d2860233e1754f4dbb61a9`），在压力机核对原SHA并按原安装脚本解封。root不读取密封工具明文或任何测试PRIVATE。
5. 只有SSH、SCP、原工具安装都得到实际成功回执后，才恢复原64核应用机。用相同方式绑定它的主机公钥，核对source90b及现有七容器，复用P09数据。
6. 重新读取真实任务资格；会话过期时通过现有登录/CLI真实重签并生成新的中性packet。旧P09 packet/window/expiry保持原样。旧790/relay已过期时，不重放旧运输或修改旧C。
7. 使用独立manualV4原入口做零请求prepare；独立岗核实际材料并批准一次grant后，直接执行，不再等待人为预设S。保留400并发、60秒预热、600秒稳态、原错误/P95/吞吐断言。900秒有限运行只从实际触发开始计时。
8. 测量退出且所有写入停止后，密封原始证据、SCP回收并核SHA，随后按用户安排停止服务器并确认本轮结果。未完成正式稳态或指标失败必须如实记录。

## 本地命令示意（不会连接服务器）

```sh
python3 pin_ssh_host.py --report LOAD_SSH_REPORT.json \
  --instance-id i-bp13uag4r4u9r2hge0mu --public-ip ACTUAL_PUBLIC_IP \
  --identity /绝对路径/本机已有私钥 --output-dir /绝对路径/私有连接目录
```

生成配置后，才在用户准备恢复时使用 `ssh -F 生成配置 t44-manual-load ...` 和 `scp -F 生成配置 ... t44-manual-load:/root/...`。私钥不上传、不打印、不提交Git。若直连失败，先根据实际错误检查SSH服务/端口或网络，不自动购买、扩容、开放公网或放宽SSH安全设置。
