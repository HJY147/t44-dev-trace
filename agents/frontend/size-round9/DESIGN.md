# 前端真实规模审计：round9

依据为总协调本轮派工 `ROLE-frontend-SIZE-ROUND9-v1`，基线为
`043fc464acd327f6b7639e89dbe4f603fc524880`。上限仍是原固定 cloc 2.10 口径的
5100 行；不改计数器、后缀、目录、注释规则、已冻结接口或视觉要求。

本轮先审核是否存在真实重复，再决定是否实现。若没有正收益，不创建仅为减行的
DSL，也不将 UI 标签搬到不计数的配置文件。正式实现必须在这一设计之后另立产品提交。

审查范围为已提交 `frontend/src/` 和 `frontend/index.html`。保留米色浅咖啡配色、玻璃
透明效果、圆角、键盘导航、无障碍状态、响应式和减弱动画/透明度退路。前端仍只展示
冻结 API 的业务判定，不能用隐藏按钮替代后端鉴权和门禁。

| 候选 | 当前结构 | 可行性与边界 | 决定 |
| --- | --- | --- | --- |
| 以 schema 统一表单 | `FieldEditor.vue` 已递归解析对象、数组、字典、时间和锁定字段；`OperationForm.vue` 已共用提交/重试/冲突流程 | 再为每种业务生成新表单会增加源码；当前没有重复的独立 CRUD 表单可删 | 保留 |
| 共用七个工作页面 | `WorkspaceView.vue` 已按页面/栏目选择同一列表、筛选、详情和操作入口 | 再做页面定义 DSL 需要参数与生命周期适配，不能删除每页面的上下文要求 | 保留 |
| 共用异步刷新生命周期 | `TaskDrawer` 和 `WorkspaceView` 均有 sequence/busy/failure/finally | 约 13 行重复初始化/结束可移除，但可读、有类型且支持取消的 helper 约需 20 行；TaskDrawer 还显式检查发起 token，WorkspaceView 依赖 API 的会话检查和 watcher 递增 sequence；不可误合并为只检查活跃状态 | 不实现净增候选 |

| 合并 CSS | 原样式已集中，基本一条规则一行，多个 selector 共用 glass/flex/表单与响应式规则 | 相同单个声明可抽 token，但新增 selector/token 行抵消删除；合并不同 cascade/specificity 会增加视觉回归风险 | 不靠压行或牺牲视觉减行 |

预期交付为精确固定口径的规模分解、现有共用结构的位置、被否决候选和未运行事项。
没有产品改动就不重跑无关 CI、浏览器、MySQL 或性能测试，也不新增镜像实现的测试。
此结论只表示本轮前端没有可信的 150–400 行真实削减方案，不表示全项目无法优化。
