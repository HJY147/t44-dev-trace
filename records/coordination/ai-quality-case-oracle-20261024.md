# AI 测试质量案例：断言也必须追溯需求

本文是 AI 总协调记录的过程事实，供胡锦洋本人随后手写研究报告时核对；不是学生亲写的研究报告或个人感想。

- 原独立测试实例在接触被测版本前冻结工具和计划；本轮实际只执行一次严格验证证书的 HTTPS 登录，返回200。计划1396条目不能算实际执行1396项。
- 客户端冻结断言要求响应头 X-Request-ID 与 JSON meta.request_id 相同；二者不同后，准备阶段停止，400客户端、预热、正式计时均没有开始。
- 测试岗私下认证完整加密证据，并复核原始任务书、需求、业务规则及接口契约，发现四份允许依据未明确要求这两个字段相等。因此原断言属于依据不足的跨字段假设，不能由此声称产品违反需求或性能不达标。
- 原冻结、失败与完整960字节密文均保留。总协调只收到明确发布的中期发现，未读取未公布的私有用例、驱动、运行日志或私钥；随后新建不继承开发上下文的独立实例，依据原规范审查复用工具，重新冻结时保留变更依据。
- 开发岗另外从公开源代码定位 API 与网页代理各自生成关联ID；总协调另做一次不带凭据的只读请求，实证该401路径有两个原始响应头。这项开发观察不能冒充原独立登录的原始线报文证据，不能回推所有请求。
- 修复设计与测试依据复核分开留痕：产品可改善关联一致性，但不能把为满足无依据断言而改代码包装成需求合规修复，也不能在测量中悄悄换版本。
