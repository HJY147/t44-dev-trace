# 用户问答与选择记录规则

记录格式版本：`gqa-v1`。这是指导岗的内部留痕格式，不代表业务接口已冻结。

## 文件与责任

- `source-questions.md`：总协调提供的已发生问题来源；保留原文，不追补成逐字聊天记录。
- `question-log.md`：指导岗逐条整理问题、当前回答、证据和待办。
- `decision-log.md`：分别记录用户实际选择、AI 建议和待确认事项。
- 用户操作说明放在 `docs/user-guide/`；产品尚未实现时不得把设计步骤写成已可运行功能。

## 后续处理方式

1. 总协调转交用户新问题，附原文或可定位证据。指导岗使用连续的 `QA-xxx` 编号，标明来源是否逐字原文。
2. 用简明中文回答；需要模块事实时向总协调或对应责任岗索取版本、命令和证据。指导岗不直接联系独立测试，也不向其发送解释。
3. 将“已解释概念”和“已验证系统行为”分开。建议、设计、实测、用户决策、用户亲自操作分别标注；没有执行证据就记录未执行。
4. 回答已给出仍可保留待办。用户明确确认后才记录已理解或已批准；若无确认，状态只能写已答复、待补证或待用户决定。
5. 涉及业务契约、字段规范、状态出口、规则或技术基线的变更，由总协调转交责任岗；指导岗只能记录，不自行冻结或修改。
6. 若用户真的修改代码，保存前后差异、文件、原因、操作者与证据。AI 修改不能算作用户亲自修改；幻觉只能记录真实发生且有原始建议依据的条目。
7. 将新答复和未决问题交给总协调；文档岗可读取本目录用于材料汇总，个人研究报告中的体会仍须用户本人提供。

## 单条问答模板

```text
ID：QA-xxx
发生时间：实际时间；原始记录缺失则写“未记录”，不得使用整理时间替代
整理时间：ISO 8601，含时区
提问者与原问题：逐字原文；若仅有摘要则明确标注
来源：文件/消息定位，以及逐字原文或来源摘要
责任岗与关联需求：guidance / 其他责任岗 / FR、AC（适用时）
当前回答：已实际给出的解释；本次新建议须另标
回答状态：未答复 / 已答复 / 待模块补证 / 待用户决定
执行证据：已运行命令和真实结果；无则写“无”
决策与操作状态：谁决定、谁操作；未发生则明确写未发生
待办与对接：下一步、责任人、所需资料；不设置虚构期限
更新历史：时间、修改者、修改原因与来源
```

## 单条决策/操作模板

```text
ID：DEC-xxx 或 PROP-xxx（建议）
类别：用户选择 / 用户委托 / 用户亲自操作 / AI 建议 / 待决事项
原值与新值：只写有依据的内容，首次选择可写不适用
决策者、实际操作者：分别记录
发生时间、整理时间、来源证据：分别记录，未知不补造
影响范围：相关规格、代码或材料；未实现须注明
状态：已表达 / 已委托 / 建议待定 / 已执行且有证据
```

敏感信息只记录用途及安全引用位置，不记录口令、Token、私钥或云凭据。所有规则变更须保留原值、新值、生效时间、影响范围和拍板人；未获决定的提案不得写为生效规则。
