# Neutral private input shapes (772-v1)

Do not fill actual values into PUBLIC. These shapes specify factual environment data, not expected bugs or developer assertions. Existing tokens are supplied once privately; no password or secret appears in public hashes or operation logs.

sessions.json: object with keys manager, developer, reviewer, service. Each is {token: string, user_id: integer, expires_at: RFC3339 UTC, project_ids: [integer], scopes: [string]}. Human identities are actual roles, not AI persons; service scopes include escalation:write. All expiries must be later than the whole new grant end. Sessions must already exist and remain unchanged.

inventory.json: {schema: '772-inventory-v1', captured_at: UTC, rule_version: positive integer, clients: [exactly 400 objects]}. Each client object is {client_id: integer 0..399, project_id: integer, transition_task: complete current Task snapshot, escalation_task: complete current Task snapshot, escalation_event: complete existing current highest-priority EscalationEvent snapshot, project_manager_ids: [all active manager IDs]}. Inventory is factual, without expected response/error annotations. All 800 task IDs are distinct; transition tasks must be developing and owned by the actual developer; no external writer may target benchmark-exclusive tasks during the window. Dependency facts and member/iteration capacity facts can be supplied as additional neutral snapshots if needed to prove eligibility. Overall fixture counts and immutable fixture digest are declared separately; a neutral count attestation may later be compared to independent observations.

A source-free Linux AMD64 Python 3.12 image is identified by exact image digest/root. It must have CA support and native Python stdlib modules including ssl, zlib and resource; no package installation is allowed. Runtime/identity/fixture/OpenAPI digests are fixed before authorization. Log-encryption key and capsule-transfer key are generated privately by the independent tester; the coordinator copies only opaque capsules and hashes. Grant environment hash covers exact environment bytes. Run output directory must not exist before the one-time receipt is consumed.

The grant window is fresh, explicit, and long enough for start, 60s warmup, 600s steady, <=15s drain and <=40s postchecks; tester hard stop is min(absolute grant end, monotonic granted duration). No old packet/session is renewed or repurposed.
