# U002 优化稿：GitHub 协作与阶段留痕

- 来源：`U002-original.md`；关联补充：`U003-original.md`。
- 版本：U002-O1；整理者：AI 提示词工程岗；状态：proposed，尚未作为实际派工使用。
- 本稿承接 U001 的多岗位组织，追加 GitHub 协作与审核要求；不把岗位分叉计为同一 prompt 的演进。

## 优化正文

请为这个项目在我的 GitHub 账号下创建一个公开开源仓库，并克隆到本地。可见性按我后续补充的开源要求执行。若该仓库已创建并完成克隆，先核对并沿用现有仓库，避免重复建立。

在既有多 agent 团队分工上，按任务依赖和项目约定的顺序推进开发。每个责任岗完成自己的阶段性任务后，由该岗提交自己的产物，保存明确的版本和提交记录，便于追溯修改者、修改内容、依据和验证结果。

各岗通过 GitHub 的 Issue/PR 沟通跨模块需求、发现的问题和待对接事项；对接记录须能关联到相关任务、接口及代码版本。遵守已有职责边界，不覆盖其他岗位的工作。Git 分支、工作区及共享索引的安排按项目协作规范执行。

新增一个专门的审核 agent，审核其他责任岗的阶段成果和对应版本，提出有证据的问题，并在修订后核对新版本。审核岗与原有独立测试岗分别承担职责，继续保持 U001 的测试上下文隔离要求。

请把我提出的两段原始 prompt 列为最终报告的亮点候选：第一段是 U001 的多岗位分工、独立测试和过程留痕；第二段是 U002 的 GitHub 阶段提交、跨岗沟通和专门审核。展示时保留我的原文，说明 AI 如何整理成可执行规范，并引用实际 Issue、PR、commit 和后续验证证据。U003 作为公开开源可见性的补充一并关联。

亮点选择应区分“用户提出的协作设计”与“执行后已经证明的效果”。证据不足时只表述为候选及设计意图，不预先宣称提高了质量、降低了缺陷或完成了验收。

## 当前执行边界

本稿是归档建议稿，不替代已经实际发送的派工消息。仓库创建、克隆、提交、审核是否发生，以其实际记录为准；本岗本轮只交提示词与亮点候选资料，不执行产品实现或替其他岗提交。
