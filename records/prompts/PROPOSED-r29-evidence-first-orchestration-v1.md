## 建议正文

请沿用已授权的固定岗位和 GitHub 留痕流程。先绑定准确源码 SHA、公开输入、责任目录、实际执行环境与允许的动作；原失败、旧授权、旧输入及原结果保持可恢复。没有新的明确执行授权时，只完成本地准备和文档。

每个接口先列真实 CLI 输出的字段、类型和语义，分别说明 prepare/status/idle，不根据近似名字假设它们同形。字段缺失应拒绝并留原件；明确 roles/TLS401、resource action/unit/PID/progress各自证明什么。

在进入新计算窗口前，由相应责任岗在与目标相同的 Linux/Python/镜像环境，对最短的无SUT CLI链核验启动器、导入路径、环境变量、权限、输出schema和落盘。把回环TLS、mock、fake API和语法检查的范围写清；它们没有覆盖的路径继续标记未验证。对 `-I` 等隔离参数，明确其对脚本目录和 PYTHONPATH 的影响，核实际模块可达性；不在云上靠重试摸索。

执行前把完整命令、精确输入hash、进程身份、单次label及停止路径准备成可审查产物。真实失败后先核副作用和未执行范围；需要继续时只按已获授权追加新label，绑定原失败与同一输入，保留旧日志，不自动重跑整链、重签grant、延会话或降低断言。

将准备、实际发压、runtime结果、性能判定、资源封存和provider停机分别记状态。没有runtime结果只记未取得结果，不推断SUT总请求数或业务失败；采集器自身0请求不冒充测试运行0请求。短测时长、P95、HTTP202接受和消息投递各自举证。

把封存、完整尾段核对、owned服务停止、保盘节省停机与自动释放复核列入结束条件。界面连接失效时先保留前缀与明确阻塞，再通过已授权可用入口恢复；最终provider状态以实际回执为准。保留的存储费用未核算时不报精确总成本。

由各AI责任岗提交自己的公开产物和准确SHA，由审核岗绑定准确版本说明范围；修改后重新核对。CI、规模和性能结论分别出证据。不同阶段重叠的测试不相加，旧源码结果不转挂新源码。用户决策、AI实现、AI测试器修正、工具故障分别归属，不记作学生亲自改码或识别幻觉。

最终交接提供实际prompt的逐字正文或明确标识的摘要、used/proposed状态、反馈与产物对应、未验证项和公开链接。没有新用户可公开原话就留缺项，原文不改，财务和凭据不复制，个人研究报告由学生本人据事实撰写。
