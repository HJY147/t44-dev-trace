# U001 优化修改说明

- 原文：`records/prompts/U001-original.md`，保持原样。
- 优化稿：`records/prompts/U001-optimized.md`，版本 U001-O1。
- 本轮实际派工标识：`ROLE-prompt_engineering-BOOTSTRAP-v1`；对应任务文件 `agents/prompt_engineering/TASK.md`。
- 修改者：AI 提示词工程岗。用户原文属于用户输入；本次整理不是用户亲自改写或人工代码修改。
- 使用状态：优化稿已归档，尚未作为实际派工消息执行；本轮岗位工作依据实际收到的岗位派工和任务文件执行。

| 原文表达 | 整理后的表达 | 修改理由与边界 |
| --- | --- | --- |
| “fan out subagent”“构建出一整套员工” | 十个固定岗位，由总协调按依赖和实际并发能力调度 | 保留分工协作意图；固定岗位不等于十个实例必须同时在线。 |
| 多行逐个列举前端、后端、数据库等岗位 | 编号列表，明确每岗职责 | 修正“专门服后端”等笔误并便于派工；不追加业务功能。 |
| “专门负责消息列表” | 消息岗，具体范围按项目需求和接口约定确认 | 原词保留可追溯性，避免把“列表”直接改成用户明确要求的某种中间件。团队当前范围见协作规范，属于后续项目解释。 |
| “消息不通”“没有上下文”“防止作弊” | 新建无开发历史的独立测试实例，中性输入，总协调转交问题 | 将独立性要求落到可审计流程。具体隔离方式来自当前团队规范，不声称共享文件系统构成操作系统级隔离。 |
| 各岗需写代码、对接、记录及本部分报告 | 实现阶段完成代码与必要自测，约定输入输出和错误版本，保留模块报告 | 整理可核对交付物；当前初始化阶段明确未实现，不越权立即编码。 |
| 文档岗“和每个部分的负责 agent 问取”信息 | 主动收集有证据的岗位事实，测试只接收冻结报告 | 保留主动收集要求，同时遵守用户更明确的测试隔离意图。 |
| 用户指导岗回答零碎问题并记录 | 记录问题、回答、依据和用户决定 | 将“记录好”细化为可回查字段，不增加新的业务工作。 |
| 用户 prompt “美化一下” | 原样保留原文，另存优化稿和修改说明 | 改善结构和可执行性，防止覆盖用户原意或把 AI 整理算作用户修改。 |
| AI 自动化迭代需写好、记录 prompt | 保存实际使用文本、原因、上下文、结果与产物对应 | 区分建议稿与真实派工；不重建未发生的历史。 |
| 最后需专门记录 prompt | 真实修订计入演进，岗位分叉不自动计为同一 prompt 的版本 | 结合任务书留痕要求明确真实性规则，不为达到六版指标补造。 |

- 尚需后续任务确认每次实际提示词的正文、上下文快照和产物版本；这份优化稿不能替代实际派工证据。
- “消息列表”的最终功能范围由总协调结合原始业务需求和责任岗契约确认。本轮不修改共享规范。
