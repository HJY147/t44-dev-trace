## 可执行的优化正文

请为本项目建立固定的多 agent 协作团队，由总协调根据任务依赖和工具的实际并发能力分批派工。固定设置以下十个岗位，每个岗位应有清晰的责任目录和持续保存的岗位记录：

1. 前端岗：负责前端部分的设计、代码、必要自测及与后端等岗位的对接。
2. 后端岗：负责后端部分的设计、代码、必要自测及跨模块对接。
3. 数据库岗：负责数据库设计、字段规范、迁移和数据相关对接。
4. 消息岗：承接原文“消息列表”对应的功能，具体范围结合项目需求和接口约定确认。
5. 定时调度岗：负责定时任务与调度部分及相关对接。
6. 部署岗：负责环境、打包、启动和部署相关工作与记录。
7. 独立测试岗：使用新建、无前序开发上下文的 agent 实例开展独立验收，避免通过开发讨论提前获知实现细节和预期答案。
8. 文档汇总岗：主动向各责任岗索取有证据的信息，汇总形成项目报告。各岗仍须撰写自己的部分，不能把过程记录全部交给文档岗补写。
9. 用户指导岗：回答过程中的零碎问题，提供操作指导，并保存问题、回答、依据和用户决定。
10. 提示词工程岗：原样保存用户 prompt，在保持原意的基础上另存优化稿及修改说明；对 AI 自动迭代产生的派工和修订提示词，保存实际使用的文本及其结果。

在进入各模块实现阶段后，各责任岗除完成自己的代码外，还须明确上下游的输入、输出、错误和版本约定，并保存实际执行过程、对接结果及本模块报告。当前若只处于团队建立或设计阶段，应如实标注“未实现”，不得把岗位初始化记为业务代码、联调或验收完成。

独立测试须与开发讨论隔离。只向测试实例提供原始需求、冻结的规格与接口、被测版本及必要的运行环境等中性资料；不传入开发工作日志、修复建议或预期测试结论。测试问题和缺陷经总协调流转；文档岗仅接收冻结的测试报告，不向独立测试岗注入开发解释。

过程记录必须区分用户原文、AI 优化建议、实际使用的提示词、AI 自动修改、用户审定和用户亲自修改。每次真实的 prompt 修订记录修改原因、上下文、实际使用状态和产物位置；不同岗位的分叉不自动算同一 prompt 的迭代版本，不补造提示词版本、人工修改、测试结果或个人经历。

请先完成当前阶段已授权的团队组织和岗位资料，再按后续确认的需求、契约与任务范围推进。遇到跨岗位变更，由总协调明确责任和协调顺序，避免覆盖其他岗位的工作。

## 使用提示

- 此稿是 U001 的忠实整理，不替代原文，也不自动冻结业务接口。
- 独立测试的实例创建方式、可访问资料与转交机制按根 `AGENTS.md` 和 `docs/collaboration/team.md` 执行。
- “消息列表”的具体技术解释属于项目对接事项，不在本稿中冒充用户的原始措辞。
