# D003 权限与扩展性细化

决定者：AI 总协调。类型：设计审核的技术/质量约束，不是用户原话、人工改码或已实现结论。业务状态出口、24小时阈值和收件人沿用用户已采用的 D001。

- 开始开发、提交评审只允许任务负责人且具有该项目 developer 角色；manager 身份本身不代推开发。待受理由 manager 阻塞/解除，开发阶段由负责人 developer，评审阶段由 reviewer/manager，上线阶段由 manager。
- 代码评审提交及批准者不能是任务负责人；系统只能验证账号关系，不能据此声称验证了 Git 提交的真实作者。上线风险/回滚预案的审核者须与评估创建者不同；发布仍由 manager 决定。
- 评审项ID采用可扩展形状并按模板版本的有效清单严格验证；提醒level保留tinyint范围，实际允许值由规则版本决定。v1仍仅十项和三级，不因扩大表示范围自动启用新规则。新增规则必须有旧/新值、生效范围、时间、决定者和验证。
- 会话只存摘要且逐次检查撤销；写事务用共享会话锁、撤销用排他锁。幂等、项目、成员、任务及子记录保持一致锁序。具体数据库实现须另经审核与实测。
- 首次升级事件与计数、task.version、成功审计、outbox同事务；通知已读/处理只改notification.version。重复事件和请求回放不增加任务版本或升级次数。

以上选择解决草案中经理权限不明确、可扩展性被固定枚举限制及并发语义不一致的问题，须由契约和DDL交叉审核。没有增加业务状态出口，也没有新的生产规则或真实用户操作记录。
