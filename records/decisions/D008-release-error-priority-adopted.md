# D008 发布多守卫错误顺序

状态：用户实际采用业务规则；实现、设计专审、新规格冻结和复测尚未完成。

本轮真实问题：发布任务时，“上线评估基线已过期”和“经理原批准已失效”同时发生，应先提示哪项。两项都必须满足。

用户实际选择原文：

> 先要求更新上线评估，再由经理重新批准（建议）

来源：[U021问题/回答原文](../prompts/U021-original.md)。记录者为总协调AI；选择者是用户，不是AI互审。它不构成用户亲自改码或老师同意放宽任何指标。

预期：在鉴权、项目/资源归属、请求版本与其他既定前置守卫保持的前提下，DELIVER引用的评估相对当前任务交付轮次/排期版本失效时，先返回ASSESSMENT_BASELINE_MISMATCH；只有评估基线有效时，再报告RELEASE_APPROVAL_REQUIRED。请求中assessment_version与该评估自身版本不符的原校验保持。无评估、跨任务评估、权限或版本错误不能被新优先级覆盖。两项失败都不允许发布，不重用旧批准。
