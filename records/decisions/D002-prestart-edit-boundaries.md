# D002 开始前编辑范围

决定者：AI 总协调。类型：最小 v1 技术范围选择，不是用户逐条批准或亲自改码记录。依据：D001 已采用规则要求开始前检查依赖，禁止悄悄改变其他任务状态，并按任务、排期版本及升级级别去重。

任务负责人和依赖关系仅允许在待受理，或从待受理进入阻塞时修改。已经开始的任务不提供转派或改依赖入口，返回明确冲突；不为此新增状态出口。项目经理可维护开始前的负责人和依赖，依赖修改仍须拒绝跨项目、自依赖和环。

这样可避免进行中转派触发同级通知争议，也避免已评审范围被间接改变。排期仍可按业务规则调整并保留前后差异；排期修改不撤销代码评审，但使旧上线评估失效，新评估绑定当前排期版本和交付轮次。返工或评审失败返回开发后必须开启新的评审轮次，不复用旧批准。

该限制必须显示在接口文档和页面能力中。后续若需要进行中转派或依赖变更，按新需求单独版本化设计与验收。
