# GitHub 开源协作与阶段提交

用户已授权创建公开仓库、克隆本地、各岗阶段性提交、通过GitHub对接，并新增审核岗。仓库 HJY147/t44-dev-trace，MIT；原始课堂材料、老师提供的原件、凭据和本地运行数据不提交。

## 对接与阶段提交

- 每项工作建 Issue，写 Agent-Role、需求依据、目标、依赖、产物和证据。跨岗需求与回复留在相关 Issue/PR，注明实际 AI 岗位。
- 分支使用 codex/<role>-<milestone>；产品开发使用 .agent-worktrees/ 下各自的 worktree。Git 索引不能并行操作。
- 各岗自己提交自己的阶段产物；commit 正文带 Agent-Role、Prompt-Ref、相关Issue。提交作者使用用户授权身份，岗位footer标明实际AI操作者，不冒充独立真人。
- PR说明行为、接口/字段影响、验证证据、未验证内容和模块/提示词记录。审核通过后由总协调整合。

## 审核与主干

reviewer 审核准确 HEAD SHA，提交变化后重新审核。静态检查、契约测试、覆盖率门禁失败不得合并。主干保护以实际API配置与验证为准，不能以规范文档代替。

GitHub不允许PR作者批准自己的PR。同用HJY147授权时，审核岗使用带岗位标识的COMMENT和绑定SHA的commit状态，不伪造另一真人的APPROVE。开发岗不得自行发布reviewer通过状态；授权仍属于同一用户，岗位之间是流程隔离，不称账户物理隔离。

## 独立测试

独立测试不参与开发Issue/PR讨论，只接收冻结需求/接口/被测版本/运行环境的中性包；用例先冻结。缺陷由总协调单向派发，修复复测另开无历史实例。开发与审核岗不能读取未发布独立用例或测试内部记录。
