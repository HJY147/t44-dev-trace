# 本地作业审阅包设计（不是最终提交）

作者：协调AI。先设计再实现，等待M7测试Word最终QA后才选择实际文件。目的：把可阅读技术稿、准确源码快照和真实未完成项放在一个私密ZIP中，便于用户醒来后审阅；不发布Release、不上传个人封面、不宣称作业通过。

## 输入与版本

源码包由现有build_source_review.py从准确已提交Git版本正向选择，再验证ZIP和逐成员hash，禁含独立私密载荷/运行凭据/工作树。只在稳定阶段重建一次，旧48e源码包不覆盖。

技术稿正向选择四个已逐页QA的DOCX：需求、设计、AI规格复用M6原hash；只有有实质更新的测试稿采用M7并记录自己的截止与QA。不同截止必须显式列示，不把M7标签套在未改三稿上。输入清单写在ignored私密目录，只列路径/hash/QA出处，不读取封面字段作为公开元数据。已渲染PDF和PNG仅保留内部QA，不作为未要求的交付中间件放入ZIP；此项在实际构建前按文档技能纠正最初草案。

辅助材料正向选择已公开的AI过程素材、自写提纲、提交物清单、真实提示词M6/M7和原始研究来源索引；本人原话只选已公开R001。R002原文留在已有私密位置，包内只给provenance，不复制批评原文。模板和AI材料均明确AI身份，不能冒充本人最终研究报告。

## 输出与验证

新增builder仅接受本项目真实普通文件、受限正向目录和准确hash，禁止symlink/路径逃逸/重复成员/覆盖。输出目录0700，ZIP及外部manifest0600、O_EXCL创建。包内名称使用稳定中文序号和相对路径，完整manifest逐项列源版本、SHA256、字节数、作者归属与用途；不在公开receipt中写个人字段。

ZIP写毕重新打开：核成员集合、重复/安全路径、CRC及所有逐项SHA；源码内层包以其既有签收hash校验。输出公开receipt只记录包hash/大小、技术稿版本与hash、验证结果、明确缺项，不发布ZIP或Word本体。若输入hash或QA不完整，停止创建，不静默改选旧稿或声称成功。

包内首页说明这是审阅材料，至少列：三正式P95失败、6307行超1207、F08错误优先级未决、精确故障切点/限定核查未完项（按最后已发表事实）、学生本人研究正文及12/5/3人工证据未完成。记录当时截止，不从后续资料倒填。

实际构建属于可撤销本地文件操作，无需叫醒用户。最终提交仍须本人审阅、补齐本人材料，并对未达门槛作真实决定；builder不自动合并main或更改门禁。

## 原候选版本绑定反例与窄修设计

原9d6ead5的独立builder复核只校验内层source_commit字符串及内容/hash/blob自洽，main另核commit存在。专审以唯一内存ZIP证实：声明真实commit、api.py换成另一blob且内部hash全自洽，原函数接受，拒绝断言exit1。可信上游生成器与可信输入SHA可排除此反例，但这属于额外信任前提，不足以支持新builder自己的独立Git绑定承诺。没有读取/篡改真实私密包，发现者为root自查和审核AI，不能记学生发现。

窄修保留原verify_source_archive(data,source)接口，只额外使用同目录可信build_source_review.py的正向选择器，从声明准确commit独立取得完整成员集合、git_blob与mode；要求内层集合/每映射完全一致，再做原bytes/SHA/CRC复核。CLI限定本脚本所属项目，避免拿另一个project-root的输入与本项目Git混验。原上游和包格式不改、不读Git文件内容或独立私密载荷，只查正向允许路径元数据。拒绝缺失/额外成员、错误blob/mode，不以可解析commit当作文件绑定完成。

先提交本设计，之后才改代码；原9d6失败与公开专审保持。窄修只做必要静态检查，审核岗原内存反例一次复查；通过后才实际创建审阅包，不把该限定关闭写成最终软件或课程验收通过。
