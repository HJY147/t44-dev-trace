# V2-UI-001：退出后的项目上下文清理

## 依据与复现范围

独立 v2 已发布界面报告在固定 4c20f32 记录：退出接口真实 200 后，登录表单与退出提示出现，但侧栏 rendered DOM 仍有前一合成项目名称；后退 11 秒后仍在，完整刷新才清除。缺陷单为 Issue25。本阶段仅使用已发布的报告，不读取独立用例、私密日志、截图或运行数据。此观察不证明服务端权限绕过、任务行保留或外部泄露。

当前产品 75c3468 的 workspace/logout、App 和侧栏与上述源相同：logout 只清 user/projectId/projects，侧栏仍读取未清的 project.name；401 回调也漏清 projectId、taskChoices、字典、模板、规则及上下文提示。App 的 inert 只能禁止交互，不能移除保留项目内容的 DOM。

## 最小设计

1. 成功退出和当前会话的非登录 401 共用会话清理入口，清空内存中的身份、选中项目、项目列表、项目详情、成员、迭代、任务选项、字典、模板、升级规则及上下文警告。正常退出仍以服务端确认成功为先；网络失败/503 保留会话并展示重试提示，不能假称服务端已注销。
2. 未登录时卸载工作空间与其业务路由、侧栏、任务/表单浮层、移动导航和访问说明，而不只用 CSS 或 inert 隐藏。关闭 App 内导航/说明开关，下一次登录不自动重新打开旧浮层。登录组件已有 notice，保留真实退出/过期提示。
3. 每个请求绑定开始时的 token。迟到的旧会话 401 不能清除新会话；迟到的旧会话成功响应不能交给调用方写回新身份。客户端取消使用明确的 SESSION_CHANGED 错误，不将它说成服务器 401 或证明原写入已回滚。分页、bootstrap 和 context 在跨 await 边界核对会话，context 另用请求序号拒绝旧的同项目加载。业务视图卸载后不得继续刷新或写回任务选项。
4. 不改后端、冻结契约、角色判断、幂等键、版本冲突、状态和业务默认值。已发送的写入可能在服务端完成；前端清理不改变这一事实。

## 开发岗验收范围

在既有 tmp/frontend/982_client.test.ts、983_application.test.ts 增加：退出成功清理全部上下文；非登录 401 清理；退出失败保留原会话；旧 bootstrap/context 响应不恢复身份或项目；迟到旧 401 不撤销新登录；App 退出后和 history/back 后 DOM 不含前一项目/任务，浮层不残留。先保留改前失败，再执行同一组改后及受影响现有回归、类型和构建检查。

真实浏览器使用前端岗位独占端口与允许的合成演示账号，验证桌面/手机登录→退出→后退/完整刷新、当前会话 401 后清理，保留实际请求结果与截图；需要新的测试脚本时先由总协调分配编号。不得动用户 5173、独立 5175 或独立数据库。性能诊断静默窗口未释放前不运行测试/构建/浏览器。

这些是开发回归，不撤销原独立 FAIL，不代替新的无上下文独立复测。每个失败、环境错误、执行者和未验证项单独保存；产品代码仍需另岗按准确提交审核。
