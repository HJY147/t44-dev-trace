# 项目入门与后续指导

本文供不熟悉前后端的用户理解项目；当前处于团队建立和设计准备阶段，还没有可操作的产品或已验证的部署命令。

## 这些部分分别做什么

| 部分 | 简明解释 | 本题例子 |
| --- | --- | --- |
| 前端 | 浏览器中看到和点击的界面 | 查看任务、填写阻塞原因、发起评审 |
| 后端 | 收到请求后检查身份、权限与业务规则 | 拒绝“开发中”直接跳到“已交付” |
| 数据库 | 持久保存任务及其来龙去脉 | 保存状态、依赖、评审和拍板记录 |
| 消息队列 | 将通知任务交给消费者处理 | 发送升级通知并防止重复通知 |
| 定时调度 | 按设定时间自动执行工作 | 定期找出临期和超期任务 |
| 部署 | 把这些部分放到运行环境并管理启动 | 配置环境、启动服务、备份和恢复 |

接口契约是前后端共同遵守的说明：请求要传什么、会收到什么、出错怎样表示。状态机是允许和拒绝任务状态变化的规则。幂等指同一件事重复提交或重复扫描，不会重复产生业务结果。这些都需要实现和验证，解释概念本身不算测试通过。

## 目前已经明确的事

- 你的 Python 选择已经记录；十个固定岗位的组织要求有原始请求可查。
- 八段式评审和十项清单由 AI 起草，仍需要形成清楚、可审查的模板，不能把模板当成老师提供的原文。
- 技术方案和云服务器配置已经有建议。服务器尚无购买或实测证据，建议配置不能当作性能承诺。

## 后续会怎样指导

1. 设计阶段：用具体例子解释页面、任务状态和关键决策；问题与选择保存在 `records/qa/`。
2. 环境阶段：部署岗提供最终环境和命令后，按真实环境说明购买前核对、连接、启动和报错处理。指导中不要求公开口令或私钥。
3. 使用阶段：产品功能真实可用后，再编写登录、建任务、阻塞、评审、上线与回滚的步骤，配真实页面或执行证据。
4. 交付阶段：协助理解哪些材料由 AI 汇总，哪些选择、实际修改和课程体会需要你本人依据真实经历确认。

尚未发生的操作、尚未批准的业务决定、尚未完成的测试都会明确标注。新问题交给总协调转交指导岗；涉及模块实现的答案会注明责任岗与证据版本。
