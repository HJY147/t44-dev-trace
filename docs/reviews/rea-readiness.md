## 项目辨识及范围

与“最近很火、AI逆向一切”高度吻合的项目是 [morluto/rea](https://github.com/morluto/rea)，官网为 [rea.tools](https://rea.tools/)。这是候选辨识，尚不能确认教师使用的具体版本、提示词和评分方法。

官方定位是让智能体检查应用及运行行为，并返回代码关系和证据；支持 JavaScript、网站及原生程序等目标。它提供分析能力，后续解释、重建和测试由智能体完成。以上来自官方 README 和网站，不将其推断成课程专用评分器。[官方说明](https://github.com/morluto/rea#how-rea-works)、[网站示例](https://rea.tools/#how-it-works)。

本轮只核读官方资料，没有安装或运行 REA，也没有“REA评分通过”结论。官方当前 README 的 Node 最低版本要求高于本机现有的 24.19.0；若开展真实 CLI 实验，应先按指定发行版本核对运行条件并保存版本、目标产物摘要和原始结果。[运行条件](https://github.com/morluto/rea#what-you-can-analyze)。搜索曾返回其他同名或复制 README 的仓库，因此辨识以官方仓库与官网相互链接为依据。

## 针对本项目的改进

下表是项目自己的质量检查方案，不是 REA 官方或教师评分标准。

| 检查问题 | 具体产物与核查方法 | 当前边界 |
| --- | --- | --- |
| 需求如何变成设计和代码？ | 保持 FR/AC 编号，建立“原始要求→审定口径→概设/详设→实际函数→测试”矩阵；需求图与设计图分别解释业务边界、结构和交互 | 文档岗正在更新 M2，不能把后来补充的图说成开发前已有 |
| 代码是否实现了文档中的约束？ | 审核岗沿 HTTP 入口追到鉴权、状态门面、事务、审计和 outbox；逐一核查真实调用，不只搜索关键词 | 开发岗测试已有证据；完整代码审核和独立验收仍须各自出结论 |
| 网页能否独立执行业务规则？ | 用公开 HTTP 接口复现越权、非法状态跳跃、旧版本并发、重复请求；核对错误、任务与审计数据 | 前端校验不能替代服务端守卫；以冻结 OpenAPI/业务规则判断 |
| 声称“可靠投递”是否有运行依据？ | 检查持久事件、确认、重复消费、故障降级、扫描断点及进程恢复的关联标识；区分真 RabbitMQ 与拒绝端口/模拟依赖 | 真实 RabbitMQ 用例在已有 CI 跑过；新整合 SHA 要重新通过正式门禁 |
| 图、接口、DDL和运行版本一致吗？ | 每份验收/性能结果绑定完整 Git SHA、输入规格摘要、命令及环境；图中实体/状态/进程须能指向对应实现 | 规格冻结清单是历史快照；后续说明文档迭代不悄悄覆盖冻结语义 |
| AI过程是否可以核实？ | 原始 prompt、实际派工、Issue/PR、提交、原始失败、修复 diff、复验分开保存；标注 AI 行动与学生实际判断 | AI互改不算学生亲自改码；提示词岗记录不能冒充学生亲写研究报告 |

REA 自身的测试指南强调实际边界与公开工作流，并区分模块、边界和验收层次；本项目据此检查证据深度，不照搬它的工具测试名称充当本项目用例。[官方测试指南](https://github.com/morluto/rea/blob/main/docs/testing.md#behavioral-depths)。

## 进入最终评审前

由审核岗在确切整合 SHA 上出具实现与文档一致性意见；由无开发上下文的测试实例先冻结用例再执行；保留失败和未运行项。400并发10分钟、P95及代码规模等任务书指标仍按原始要求验收，不能由静态逆向分析或一份解释报告代替。

学生自写研究报告可根据实际证据回答：某个需求为何被拒绝或澄清、哪条 AI 建议经测试被推翻、如何从错误定位到修复、自己做了什么判断、仍有哪些方法局限。这里提供证据索引和问题，不预填学生个人收获。
