# 新诊断准备：职责与网络边界

源935诊断库已实际核40项目、6000任务、9000依赖，候选600/2080足够400组。第一次单进程准备失败原件保留；原管理容器data-only无法路由到宿主TLS（实际errno101），宿主TLS当时另因Nginx只读临时目录失败（errno111）。TLS由独立新overlay修复并实际严格CA/IP取得401；旧配置与停止锚保持。

本次采用后端岗位先行设计的S1/S2。S1仅在原data-only admin内读真实SQL候选并由原CLI签发40个实际项目的服务令牌；只接身份映射，不接密码。S2使用官方Python、单独edge网络及明确私有挂载完成真实TLS登录、GET、契约检查、创建提醒和新key去重。它不挂产品或数据库环境。两阶段由根校验输入摘要、镜像/网络所有者与完整公终态；不修改既有容器网络，不覆盖第一次失败文件。

输出为400个实际独占任务配对和合法会话私包，仅服务后续开发短窗。它不属于独立验收，不将真实600/2080候选数、CLI成功或会话存在当作正式400/600/270通过。每次阶段有全新目录、有限超时，原UTC21:00工作负载保护不变；仅最终会话私包将交同批load机器，密码和候选仍留app。
