# Frozen later-phase UI, whitebox and coursework audit

Operator is an AI. This document is a test protocol only; none of these inspections was run during the case-design freeze. Whitebox/source/CI access requires separate explicit authorization after this freeze. Browser requires exact neutral SUT binding. Preserve original freeze; do not adjust thresholds to the product.

## Browser acceptance protocol

Use an actual Chromium browser at context.web_base_url through the same reverse proxy. Record browser/version/viewport/timezone (Asia/Shanghai), product SHA, action trace, sanitized network request IDs, screenshots and DOM/accessibility observations. External evidence URLs are inert synthetic HTTPS; no third-party requests or real production publication. API-assisted setup is allowed and explicitly identified; a screen pass must be observed in the browser rather than inferred from API success.

UI01 login normal/wrong account/wrong password/logout/back/reload: credentials masked, no token in URL, user identity correct, expired/revoked session returns login and no stale project contents. Test request made with invalid session against server separately; merely hidden menus do not prove security.

UI02 project list: manager has P, outsider has Q; force known foreign route/resource URL as each user. Product shows permission error without foreign name/task/state/version. After removing a member, reload and repeated navigation cannot show cached protected data. Role hiding matches actual role; manually forged API still checked separately.

UI03 iteration and staffing: manager records name/time/capacity/buffer/contingency, proper 0.25 precision and timezone. B absent from capacity cannot be assigned by forged server command; browser must show server error and keep current owner/version. Add B, assign pending task, then attempt removing active owner capacity; clear reason displayed and no false success. Delivered/rolled-back owner can leave capacity, rolled-back member cannot be removed. Rework after missing capacity displays rejection; restore capacity and legal rework shows new cycle/state.

UI04 task/dependency plan: create dependency chain, unsatisfied task displays blocker; forced start rejected server-side. Valid dependency delivery updates satisfied indicator. Self/cycle errors display; state/owner remains unchanged. Plan edits show before/after, reason/evidence, actor/time and version; task and iteration plan are distinct. Sorting/pagination/filters stable with >100 records and tied times.

UI05 state machine: walk pending→development→blocked→development→review→release→delivered→rolled-back→rework. Block requires reason/responsibility/evidence; unblock requires basis and server-selected prior state. Manager cannot impersonate developer start/submit. On concurrent stale form submit, server409 appears and current authoritative task is refreshed. A replayed old successful response must trigger latest GET so old snapshot does not overwrite newer state on screen.

UI06 review: eight sections/ten items visible, per-item evidence location; pass with missing evidence/duplicate item/unverified required item disallowed server-side and visibly explained. Owner cannot publish/approve own task; reviewer identity/SHA/version and latest cycle displayed. Rejected review and old review history remain available. AI-created fixture evidence is labelled synthetic, not student verification.

UI07 assessment/delivery/rollback: data, permissions, external dependency, observability each represented, mitigation and complete rollback plan. Same creator cannot approve; unreviewed/stale assessment cannot deliver. Reschedule preserves code review and invalidates release approval. Separate manager decision includes reason/impact/target/evidence; rollback preserves task/history and does not imply external deployment occurred. Test UI records are synthetic decisions, not real human production authorization.

UI08 notifications: actual broker/scheduler-generated notice shown to owner/all managers, fallback marker present under broker fault, duplicate does not add reminder/reset read/handled. Read and handled are separate controls and states; handling requires note/evidence and never changes task state. Another recipient and former member cannot access notification. Escalation counts, handling results and old plan versions inspectable.

UI09 safe rendering: submit ordinary apostrophe/SQL discussion and inert HTML/script marker in title/description/evidence locator. UI renders text safely, no script execution or javascript URL, no credential copied to console or displayed logs. Evidence links with unknown/unsafe schemes remain non-executable; repository reference revision visible; no automatic server fetch of HTTPS proof. Test only harmless script marker setting a local DOM attribute; never exfiltrate.

UI10 accessibility/robustness: all task actions keyboard reachable, status/errors labelled, required fields obvious, narrow viewport readable, no uncaught console errors during successful flows. UTC fixture read back as expected Asia/Shanghai date/time (including day boundary); raw payload remains UTC. Network outage/restoration and refresh after a committed change preserve server facts, no phantom local success.

Verdict for each UI case: precondition reached, screenshots/network observation, expected/actual, PASS/FAIL/BLOCKED/NOT_RUN. Missing browser or inaccessible frontend prevents UI acceptance, even when API tests pass.

Use source syntax/semantic tracing rather than keyword-only claims.

Review migration sequence/backup/recovery evidence bound to exact DDL and four-table review. Application startup must not create_all/migrate implicitly. A DB shape check cannot prove centralized application enums; inspect real read/write mapping and guard paths.

WB03 FR06 transaction trace: authenticated entry→shared Schema→idempotency→project/member/task lock ordering→domain state machine→CAS→associated review/assessment/decision/diff/audit/outbox/result→single commit. Confirm API cannot assign arbitrary state or bypass state machine; project consistency lock for staffing/dependency. WB04 FR07 MQ/scheduler trace: durable/persistent queue/exchange and publisher mandatory+confirm, consumer DB commit before ACK, read-authoritative event and recipients, outbox lease token ownership, fallback/consumer shared lock, unique(event,recipient), late confirmed event does not undo fallback, read/handled never reset, all active managers without100cap. Complexity O(N+recipient expansion), DAG O(V+E), memory page bounded; explain real code and queries without performance claims from asymptotics.

WB05 security: one actual auth entry for all38protected operations except login, current membership and service scope, expired/revoked sessions, write-transaction recheck and lock linearization. Account initialization input accepts clear password only transiently, persistence gate accepts parsed safe Argon2id hash only. Independently attempt plaintext storage via authorized isolated persistence fixture and check durable rejection; never alter production database. SQL uses bound parameters, no SQL building from identifiers without whitelist. Canary secret absent from ordinary logs, audit before/after, idempotency snapshots, event payload and public output. Token digest irrecoverable, CLI revoke all/single available; no original token in command arguments.

WB06 engineering: resolve actual module imports/calls to facades and constructor injection. Static checks, contract tests and ≥80% coverage are three distinct required gates; test source denominator/cfg excludes only legitimate non-application/generated files. Execute complete required suite on bound SHA; capture commands, exit codes, versions, junit and coverage raw data. An existing report or developer statement is only input for repeat execution, never independent pass. Do not lower coverage threshold or exclude failing modules.

WB07 real repository merge controls: authorized read of branch protection/ruleset API, required exact contexts, strict update policy, administrator behavior and PR-only process. Use a dedicated synthetic candidate PR/branch with one independently observed failing required static/contract/coverage condition, retain actual merge attempt refusal and server response; never weaken main protection. After responsible developer fixes, use new full head SHA and retain original failed evidence. Review context must be from authorized review role and exact SHA, not own same-account APPROVE fiction. A passing badge/config screenshot alone is not actual failed-merge evidence. If merge attempts are not authorized or have irreversible real effects, mark this specific exercise blocked while read-only inspection proceeds.

WB08 maintainability: two separate synthetic branches from bound SHA. Add a required review item and a new escalation rule via authorized configuration change, each ≤1 config+1 module, no DDL/API hardcoded enum/front-end rewrite. Freeze original/new/effective/impact/decider; run old and new required-template/rule tests, boundary/time/recipient/priority cases. Count actual changed paths and log actual AI elapsed effort as AI; ≤1person-day claim needs a defined real measurement, not invented student work. Do not adopt new production business rule or change original SUT. Restore untouched original checkout.

WB09 effective size: retrieve cloc2.10 from official fixed release and verify tool SHA; from exact Git SHA archive only backend/t44,frontend/src,frontend/index.html; count Python/TS/Vue/CSS/HTML nonblank/noncomment. Report per-file/group JSON and limitations, range3500–5100. Tests/config/deployment/CI/authoritative DDL/contracts/rules/generated/dependencies separate, copied product contracts/DDL not double counted. Inspect for padding/trivial split lines without altering fixed metric. Frozen source-counting policy is authoritative; do not use test lines to meet range.

## Coursework artifact and provenance audit (later authorized records access)

DL01 final code+tests/report+requirements/design+AI executable specs/instruction explanation+AI-era software-development research report+individual course reflection. Required architecture comparison ≥2candidate sets on performance/cost/maintainability, state table/reject conditions, errors, core-field/DDL review, scan/idempotency pseudocode+complexity. Exact documents/paths must be provided neutrally; present whitelist links do not authorize reading other files now.

DL02 prompt evolution ≥6versions, ≥12real human modification contrasts, ≥3actually occurred hallucinations, ≥5context→finalcode mappings, each with real actor/time/source/diff. A role branch is not prompt evolution, AI edits are not user edits, a generic potential hallucination is not an actual occurrence. Teacher assignment asks for the person's views on AI's impact, quality by stage, collaboration/mistakes/strengths/course suggestions. Missing personal contributions stay missing; AI may organize authentic supplied material but cannot claim to be the person.

DL03 explicit final state exit/closure, fields/errors and real rollback decision authority. D005/D006 actual adopted choices are checked separately from AI technical edits. Change records keep original/new/effective/impact/decision-maker; do not rewrite old freezes/results into1.1pass. Read-only evidence statements are never counted as human intervention absent direct provenance.

Conclude only after every required phase has evidence. Bound failures, unrun, blocked, specification ambiguity, unreachable branches, residual machine limits and environment limits remain visible. Preserve private notes and publish only a reviewed final report explicitly released by the independent tester.
