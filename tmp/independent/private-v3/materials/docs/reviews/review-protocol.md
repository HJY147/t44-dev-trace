# 阶段 PR 审核协议 v1

状态：初始化设计，尚未执行真实 PR 审核；`ROLE-reviewer-BOOTSTRAP-v1`。依据为 `AGENTS.md`、`docs/collaboration/team.md`、`docs/collaboration/github-workflow.md` 与 `agents/reviewer/TASK.md`。

## 输入与职责边界

总协调提供 Issue/PR 链接、仓库、base SHA、完整 40 位 head SHA、原始需求/冻结规格版本、变更范围和责任岗。责任岗提交接口与数据库变更、运行环境、实际命令及退出码、原始结果路径和未验证项。独立验收只接收总协调发布的冻结结论及其被测 SHA，不读取未发布用例、测试工作日志或内部讨论，也不联系独立测试岗。

审核人核对 PR 当前 HEAD 与所给 SHA，并固定差异及证据版本。缺少确切 SHA、需求基线或必要证据时，停止通过判定，列出缺项交总协调。只审其他岗位产物，不审核自己编写的产品代码，不替开发修实现、删改断言或补造证据。

## 八段式审核输出

每次报告位于 `reports/reviews/<PR号>-<完整head-SHA>.md`，GitHub COMMENT 指向该报告及原始证据。

1. **审核对象与基线**：PR/Issue、base/head SHA、需求/接口版本、审核人角色、时间、范围及排除项。
2. **需求映射**：需求/验收项到差异文件、入口、行为及证据的对应；区分冻结要求与草案。
3. **变更与责任边界**：变更目的、真实差异、责任岗、跨模块影响、生成物及原始材料/凭据排查。
4. **接口与数据库兼容**：输入输出、错误、字段/版本、调用方、迁移顺序、约束、存量数据及回退风险。
5. **业务正确性**：状态迁移、事务、权限、幂等、重试/并发/失败恢复的代码路径和待证实行为。
6. **执行与证据**：实际环境、命令、退出码、原始结果、覆盖范围；分别记录自测、集成与总协调发布的独立验收结论，标明未运行项。
7. **问题与门禁判定**：逐项检查表、可定位问题、需求依据、影响、复现/静态证据、阻断性、责任岗及缺失证据。
8. **结论与复审条件**：通过/不通过/未验证、绑定 SHA、待办与复审输入；列明合并由总协调执行，审核结论不等于产品验收通过。

## 十项检查清单

逐项写 `通过 / 不通过 / 未验证 / 不适用`，附路径、行号或命令/运行链接；不适用须说明理由。

| 编号 | 检查项 | 必需核对内容 |
| --- | --- | --- |
| 1 | 审核身份与版本 | 角色、作者、需求基线、base/head SHA、实际差异一致；无自审产品代码 |
| 2 | 需求与范围 | 功能及验收映射完整；未悄改需求、测试断言、覆盖率分母或门禁 |
| 3 | 接口兼容 | 请求/响应、错误、版本、调用方及跨岗确认；破坏性变更有明确方案 |
| 4 | 数据库兼容 | 字段、约束、索引、迁移/存量数据、事务边界及回退影响 |
| 5 | 状态机 | 合法迁移、前置条件、非法/重复操作、状态与副作用一致 |
| 6 | 权限与数据边界 | 身份、角色、项目/资源权限、越权及服务端校验；无明文凭据 |
| 7 | 事务与并发 | 原子性、竞争条件、锁/唯一约束、部分失败及一致性恢复 |
| 8 | 幂等与故障 | 重投/重试/去重、确认与失败路径、消息及调度重启语义 |
| 9 | 测试证据真实性 | SHA、环境、真实命令/退出码/原始结果、覆盖范围；自测与独立结论分开 |
| 10 | 门禁与可合并性 | 静态、契约、覆盖率检查全部成功；阈值及排除规则已冻结；实际保护配置有证据 |

## 判定、失败与证据不足

- 任一必需项失败，结论不通过；缺项、未运行或无法绑定版本，标未验证并阻断放行。草案、截图或“已完成”不能替代原始结果。
- 静态检查、契约测试、覆盖率任一门禁失败不得合并。阈值/统计范围由总协调按原始要求冻结，审核岗不自行降低。
- 每个问题写文件/行号或运行证据、具体触发条件、违反的要求、影响和责任岗。无法证实的问题写待核实，不编造缺陷或通过结果。
- 修复只由责任岗执行；总协调分发独立验收缺陷。失败日志须保留，后续成功不能抹去原失败记录。

## 提交变化与复审

新增提交、rebase、force-push 或 base 更新导致审查差异变化后，旧结论保留为历史，不适用于新 head。读取新 SHA 与差异，重新核对受影响的十项和原阻断项，重新运行受影响检查或要求对应原始证据；报告重新绑定完整 SHA。必要检查未完成前，新 SHA 保持未通过。

## 同账号评论与审核状态

GitHub 评论/Review 正文包含 `Agent-Role: reviewer`、`Prompt-Ref`、PR 与完整 head SHA，使用 `COMMENT`。同用 HJY147 授权不能伪装独立真人，也不能作者自我 `APPROVE`；这是流程隔离，不是独立账户或系统权限隔离。

使用绑定提交的状态上下文 `reviewer/stage`：审核中 `pending`；证据完整且必需项通过为 `success`；发现阻断问题或必需证据不足为 `failure`；读取/运行设施故障导致无法审查为 `error`。状态描述和目标链接指向上述 SHA 的八段报告，开发岗不得代发 reviewer 通过状态。该上下文在初始化时尚待配置，当前配置事实见下文；协议本身不产生门禁。
