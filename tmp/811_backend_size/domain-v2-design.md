# Internal domain API v2 (authorized by total coordinator)

The REST/OpenAPI/DDL contract remains unchanged. The old internal dataclass/Command constructors and decide(position, command, context) are intentionally replaced. They were an implementation choice, not the frozen external interface. Pure domain now receives a frozen `Transition` containing trusted persisted task/review/assessment/decision mappings, the selected action/body, immutable roles and predecessor states, owner/membership booleans, precomputed checklist completeness and a prevalidated new-plan mapping. It returns an immutable `Decision` containing the read-only task patch and optional persisted decision type. Integer state/action/role/stage values come from the frozen contract's explicit enum values. Input validation rejects coerced booleans, mutable role/dependency collections, invalid positions, nonpositive counters and wrongly typed persisted identities/statuses.

Workflow remains the transaction facade: it checks expected task version first, loads and checks resource ownership in the same order, preserves assessment-version checks, the failed approval-slot state→manager→D008 priority, rollback-plan version/target prechecks, and new-plan parsing before the pure decision. Domain then checks project membership→source state→stage role/owner→details/evidence→review/release/rollback/dependency rules. Application CAS, schedule/audit recording, replay and lock ordering are unchanged. Domain rejection reasons are now strings; the transaction facade retains their existing approved HTTP error-name mapping and Rejected adapter.

Old internal test construction will be migrated through developer-owned fixture/call adapters with the same behavior assertions and legal/illegal scenarios. Separate v2 entry tests exercise its actual type-safety boundary. Exact-base semantic differential comparisons will compare v2 decisions and error precedence to the old pure decision implementation; old fixture-constructor checks will not be misreported as v2 runtime safety validation. All existing HTTP/REST tests remain unchanged. Savings are measured including the new input model/validation helper; no baseline copies or tests become product logic.
