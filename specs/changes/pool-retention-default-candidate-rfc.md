# 同峰值保留连接池候选

作者：协调AI。由本轮一次开发ABBA的可核观察提出独立候选，不覆盖bc5或原正式失败；没有生产合入、正式性能改善或整体验收的既成结论。

## 依据与取舍

数据库岗已报告唯一ABBA完成，四稳态段A1/B1/B2/A2为2079/2255/2237/2113请求、全0失败；P95依次91.591041/74.471792/72.908250/92.600542ms。A为保留5、overflow10，稳态重建/关闭436与427；B为保留15、overflow0，稳态重建/关闭均0，预热各建15个、最终各关15个。这支持该短样本中减少重复建连，不是统计显著性、全部入口或400并发正式根因证明。

候选只改MySQLSettings默认pool_size 5→15、max_overflow 10→0，单进程峰值仍15。更多空闲连接是实际代价，不宣称内存零增量。当前四API worker、消息和扫描各一进程的理论连接峰值仍6×15=90；管理/备份/健康检查等连接另需预算，不能把一次观测max_connections=151当所有部署机器事实。连接按需建立，并非启动即建满。

## 候选后续澄清（不回写旧结果）

“峰值仍15”只适用于两参数均采用默认的组合；仅指定pool_size=3时，3+10变3+0；仅指定max_overflow=2时，5+2变15+2。全部显式指定的组合不变。默认六池的保留上界30→90是预算上界，不是启动即占满，不是所有自定义对象共有的硬上限。数据库869已验证相应边界；实际内存、FD及故障频率代价仍未测。
