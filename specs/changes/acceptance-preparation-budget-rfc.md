# 独立托管准备预算的显式修订

作者：协调AI。来源是独立岗位明确提出的中性能力需求，不读取其未发表案例、日志或输出。旧H及六次原请求/退出/恢复保留，不倒填正式性能结果。

独立岗位报告：五次在约330秒准备预算结束，一次先有5秒准备HTTP超时；这些上限由其工具自行选择，不是老师的400活动并发、完整600秒、P95 270ms、1000/分钟验收指标。六次均环境ready、harness已开始、退出1且最终恢复true；没有进入预热/稳态，正式状态为NOT_RUN。已达fixture数量未在失败路径采集，保持unknown，不补造。

## 中性环境变更

只把部署请求harness_timeout_seconds允许上限1200→1800秒，最低60、默认900、整数类型、精确SHA和路径、加密归档、故障租期、恢复规则保持。workflow的job上限40分钟不变，输入说明/README与中性验证守卫同步。原1200以内请求仍受其原值约束，不因新增能力延长已完成运行。更新准确中性文件hash绑定，用新R记录实际执行来源。

必要验证只覆盖改动的请求边界：1800接受、1801/59/bool/字符串拒绝，旧合法值保持，实际执行timeout仍取请求值而非无界等待。复用现有953守卫，不改任何业务/契约测试来适应产品行为，不重复无关已通过套件；无本机服务、SQL、HTTP或独立载荷读取。部署岗先记录设计、最小代码及必要目标检查，封档准确SHA/实际Issue7交接和局限。

## 独立方法修订边界

由独立岗位自己另冻H2：拟将仅准备工具预算330→900秒、准备请求5→30秒，补失败路径只读计数/资源观察。它是接触SUT后的显式方法修订，不声称纯机械修复、完整H字节相同或新的首次盲测。原数据规模、业务请求内容、成功判据、正式请求/采样逻辑、预热、400/600/270/1000、零失败要求不得削弱，不增正式thinktime，不自动重试或忽略业务拒绝。

H2的两个源分别使用新空环境，原六次保留NOT_RUN。实际准备/正式统计、H/H2差量及可比性局限由tester自审后明确发表，root只读发布摘要；若更长预算仍不足或发生真实异常，按实际退出/未达状态报告。1800和40分钟也不是完成保证，截止不构成减载或放宽指标的授权。
