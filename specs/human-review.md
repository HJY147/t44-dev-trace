# 字段与错误码取舍：供用户审定

状态：总协调推荐方案，等待用户选择；代码/DDL仍须责任岗修复和专职审核，不因用户采用取舍就视为实现通过。来源：T44任务书第12节要求人的判断覆盖“字段规范与错误码的取舍”。业务出口和三级提醒已由D001采用，本次不重复决定它们。

## 字段推荐

| 取舍 | 通俗含义与理由 |
| --- | --- |
| 业务表统一 INT UNSIGNED 主键 | 每条记录用统一数字编号；容量覆盖演示数据与后续增长，不混用字符串和不同宽度的编号 |
| 状态/角色/布尔集中定义，最小整型保存 | 页面显示中文，数据库保存统一小整数，避免各模块用不同字符串表示同一状态 |
| 任务版本、排期版本、交付轮次、评审轮次分开 | 同时编辑时防覆盖；改期不抹掉代码评审，返工不沿用旧批准 |
| UTC存储、页面北京时间 | 同一时刻不受服务器时区影响；时间只接受数据库支持的1000～9999年且精度最多微秒 |
| 成功变更与成功证据一起提交；拒绝证据另提交 | 防止“任务改了但没有记录”，也防止拒绝记录随失败回滚消失 |
| 重试结果单独保存处理请求ID | 服务重启后仍能识别原操作及其结果；不保存旧Token或口令 |

## 错误码推荐

| HTTP | 页面含义 |
| --- | --- |
| 400 / 422 | JSON格式错误 / 字段、证据或时间不合要求，指出需改之处 |
| 401 / 403 | 身份失效需重新登录 / 没有项目或动作权限 |
| 404 | 已授权范围内找不到记录 |
| 409 | 状态、版本或依赖有冲突；保留表单并刷新，不自动覆盖他人修改 |
| 413 / 429 | 请求太大 / 登录尝试过快；提供明确说明及重试等待 |
| 503 | 必要存储不可用或提交结果不确定；不能谎称已写审计，同一操作保留原幂等键重试 |

消息队列故障而事件已可靠保存时，升级入口仍可返回202“已受理”，后续生成有标记的站内待办；202不表示已送达。无权访问不回显其他项目的状态与版本。
